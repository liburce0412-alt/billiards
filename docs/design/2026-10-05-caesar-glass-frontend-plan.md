## 基准与优先级

视觉与交互基准是用户已在手机上使用并明确认可的 **Caesar v2.1.2 实际效果**。
采用整套材质、触点追光、边缘流光、背景氛围和开关语义，不缩减成“玻璃风格”一句话。
旧生成概念图，以及泛白、彩光过浓、开关不能完整关闭效果的历史版本不作为目标。
以前的“纸白 SPECTRA 面板”描述不能覆盖本次高通透要求。

运动本身仍优先：贴拍与发球流程、真实触球与旋转、握拍/正反手、鼠标与触控手感、
动态视野和局内可见性。前端共用部分重构为这些目标服务，不能用装饰替代运动体验改进。
保持 TypeScript / React / Three.js 架构；Android Compose 是效果与交互参考，不照搬平台 API。

## 必须保留的设计语言

### 1. 玻璃材质与清晰前景

- 高通透、薄底色，实际背景或场馆能透过面板看见。细窄高光轮廓、边缘折射、RGB 色散和克制彩色反光共同形成厚度与层次。
- 材质采样背景，文字、图标和真实点击区域单独保持清晰与稳定，不随折射或形变扭曲。
- 避免大面积白色半透明填充加重模糊造成白雾、灰罩；减少外层大卡片包住内层大卡片的重复叠加。
- 局内薄玻璃透出的是实际 3D 场馆，不能另盖一张与球场无关的氛围贴图充当真实透视。

### 2. 跟手追光与边缘流光

- 光的位置和强弱连续响应手指/鼠标在面板内的位置；靠近哪一侧，就局部照亮那一侧边缘及紧邻边缘的一小段。
- 触点移动时连续过渡，移出/松手/取消后自然衰减，保留轻微弹性反馈。静态轮廓与动态追光分别定义。
- 边缘明暗、色散和渐变与触点方向一致，轮廓薄、细、有层次。不能变成自动绕整圈跑的固定彩虹，也不能把整块面板染色。
- 触摸反馈不抢走按钮点击、列表滚动、挥拍或击球输入；处理 pointercancel、失焦与页面离开，避免残留按下状态。

### 3. 浅深主题分别设计

| 场景     | 目标表现                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| 浅色     | 青、紫、粉等淡彩在触点附近的窄边缘自然过渡，淡但可见；去掉面板内部大面积彩色光晕，避免浓烈彩光或弱到完全看不见 |
| 深色     | 干净的白色追光为主，保持用户认可的适度强度；彩色环境反光从属，不把浅色彩虹追光整套搬入                         |
| 两种主题 | 字体/图标使用可读的语义前景色；进度、重点色可与环境主色协调，但不能因此丧失明暗对比                            |

主题明暗、多配色、Classic / Fluid 是分别处理的维度；主题切换不应破坏球技选择、正在进行的比赛或既有设置。

### 4. 开关必须控制完整效果

| 设置/状态             | 行为约定                                                                                                        |
| --------------------- | --------------------------------------------------------------------------------------------------------------- |
| 跟手边框光关闭        | 同时关闭所有动态边缘追光和相关内侧跟手高光；材质固定方向的静态轮廓仍可保留                                      |
| 总动效关闭            | 停止背景、边缘与界面装饰动画，取消弹性/动态形变，保留可读静态材质；不停止游戏物理、球员动作或必要的比赛状态更新 |
| 减少动态效果          | 稳定/减弱镜头起伏和装饰动作，保留清楚的操作反馈与比赛运动                                                       |
| 暗色极光/流星单独关闭 | 分别停止对应效果，其他已开启层保留；不能为了控制流星而把整个光幕删掉                                            |
| 后台/不可见           | 停止无意义的装饰渲染；联机及游戏暂停/重连继续遵循原有比赛规则                                                   |

开关统一传递给背景、材质和前景反馈各层。不能只隐藏一条描边，另一层跟手亮斑仍继续运动。

### 5. 背景与玻璃属于同一套环境

- 承接多种配色、Classic / Fluid 两类氛围。Classic 可以紧凑、克制，但仍有低幅环境变化；Fluid 使用更开放的曲线、流体/折射光带和呼吸空间。
- 背景缓慢、连续地变化；深色极光/光幕、星点和流星有主次，保留光幕结构，不能退化成只有星星。
- 玻璃采样、反光和强调色与当前背景相关联，避免每个面板各自叠一张无关的发光图。
- 在游戏内由实际场馆承担背景，装饰强度低于大厅；环境光带和 UI 光效不能影响球路判断。

### 6. 共用组件与页面一致性

大厅、模式选择、账号、房间、好友邀请、设置和暂停承接完整设计语言。
导航、按钮、输入框、弹窗共用材质、圆角、间距、状态颜色、边缘与交互规则。
从现有重复界面提取组件和主题；账号、好友与邀请已经共享，继续整理准备、退出及连接状态。
台球与乒乓球分别保留自己的比分数据、主要操作、镜头、规则、物理及比赛协议。

### 7. 流畅度底线

- 复用背景纹理、材质参数与交互更新，集中调度装饰动画，避免每个卡片各开昂贵渲染循环/上下文或反复重建模糊。
- 按画质和可见区域限制光学计算，沿用已有低画质与减少动态偏好；静态降级仍保留清楚前景和玻璃层次。
- 路由退出后释放订阅、绘制任务和临时资源，后台不保留无意义动画。不要通过删除已获认可的追光和背景层次来代替性能优化。
- 不另立大型性能验收工程；先用小样发现明显卡顿，再按具体问题做必要检查。

## 对游戏内 HUD 的适配

局内使用同系、更薄、更少遮挡的玻璃。比分与操作提示独立保持对比度，球、球拍、球杆、对手和落点优先可见。
玻璃面板布局避开主要球路和手势区，折射限制在材质边缘，不能改变关键目标的可辨识位置；必要时降低局内折射幅度。
不能给全场加雾、压暗或做扭曲球路的全屏后处理。背景及边缘动画在比赛中收敛，信息保持紧凑。
暂停层只在暂停时出现，继续后完整移除，避免残留灰罩。

动态视野与 UI 装饰分开：相机跟随站位，走动时轻微重心起伏，接触附近稳定观察；
相机目标是看清来球和对手，不机械复制机器人头部的所有摆动。

## 补充建议：直接改善可玩性

以下是本轮追加的建议，按与现有反馈的关系排序，尚未实施。

| 优先级           | 建议                                                                                                 | 玩家应能直接感受到的变化                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 与核心修正一起做 | 清楚的击球反馈：触球瞬间短促音效/轻量反馈；漏接时提示过早、过晚、未接触或出界等实际原因              | 知道这一拍为什么成功或失败；提示融入现有信息区，避免新增遮挡弹窗       |
| 与核心修正一起做 | 操作与结果一致：轻打、强攻、刷球在出球速度、弧线、落点和旋转上有可辨区别；辅助站位与人为改写球路分开 | 玩家能主动调整，而不是不同动作总得到相似的预设回球                     |
| 首个可玩版本后   | 在已有练习模式内加入短小的首次上手引导，按发球、控制力度、尝试旋转逐步出现；可跳过和重新查看         | 新手不用先读长说明就知道如何出拍、轻打和加旋；不新增一整套独立训练系统 |
| HUD 整理时       | 区分本局小分、大局局数和发球方；准备、等待对手、断线恢复使用明确且克制的状态提示                     | 比赛状态一眼可读，避免把球数、得分和胜局混为一谈                       |
| 模式选择整理时   | 两场馆使用真实游戏实景预览，显示当前选择，记住模式/难度/场馆；退出后可快速再来一局或回练习           | 减少重复设置，便于连续试玩并比较改进前后手感                           |
| 共用前端提取时   | 收紧样式作用范围和层级规则，组件显式使用主题前景色；装饰层不拦截输入                                 | 消除已发现的深底暗字、泛白遮挡和透明层抢手势问题                       |

先做好可靠的基础击球与解释得清的反馈，再考虑更多球技、训练内容或新模式；本轮不增加排行榜、商城等扩展范围。

## 实施顺序与发布节奏

1. **继续核心可玩性修正。** 依据试玩反馈先处理贴拍、托球/抛球/接触、握拍/正反手、轻重旋与动态视野，并补充必要的击球反馈。
2. **对齐两个前端小样。** 用一个大厅面板和一个局内 HUD 实现上述材质、浅深主题、鼠标/触摸追光、背景关联和真实开关行为。保持局内球路清楚。
3. **按小样推广共用部分。** 提取成熟的主题、组件与交互规则，覆盖模式选择、房间/邀请、账号、设置/暂停；不重写两种运动的核心。
4. **逐批上线、用户试玩。** 必要构建和明显故障检查后沿用已有部署授权发布，收集用户对球感、清晰度和玻璃交互的直接反馈；不默认恢复大规模回归、性能或多设备验证。

本轮只将这些内容并入计划。两份小样和共用组件均尚未实现，不能将 Caesar 的效果写成网页已经达到。
