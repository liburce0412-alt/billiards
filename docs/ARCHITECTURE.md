# Architecture

本文档说明 Break Builder 3D 的运行边界和主要模块，帮助贡献者在不破坏确定性、录像或联机兼容性的前提下修改项目。

## 设计原则

1. 浏览器是唯一运行平台，渲染使用 Three.js。
2. 台球运动继续使用专项物理内核，不迁移到通用刚体引擎。
3. 物理、规则和 AI 选择必须与渲染帧率、画质档位解耦。
4. 人类、AI、本地双人、录像和在线模式共用规则判定。
5. 联机仍传输已有的瞄准与击球事件，AI 内部类型不进入网络协议。

## 数据流

```text
输入 / AI 规划
      │
      ▼
比赛控制器 ──────► RuleProfile / RuleScenario
      │
      ▼
瞄准与击球事件 ──► 固定 1/512 s 物理推进
      │                         │
      │                         ├─ 球 / 库边 / 袋口碰撞
      │                         └─ 状态与计分事件
      ▼
录像 / 本地轮次 / 在线同步
      │
      ▼
Three.js 场景 + UI + 空间音频
```

## 主要模块

### 物理

`src/model/` 维护球、球桌、碰撞、摩擦和运动状态。帧循环使用时间累加器，以固定 `1/512 s` 步长推进；单帧补算有上限，防止标签页恢复或严重掉帧时形成“追帧风暴”。

物理参数通过 Profile 集中管理。渲染质量、屏幕刷新率和相机操作不得改变物理输入或结果。

### 规则

规则入口位于 `src/controller/rules/`。`RuleProfile` 记录规则标识、实现版本、来源、复核日期以及开球、自由球、分组、犯规、计分、让杆和重置行为。

新增规则时，应先增加 `RuleScenario` 固定场景，再修改判定逻辑。不要在 Bot、联机或 UI 事件处理器中复制规则。

### AI

AI 规划在 Web Worker 中异步运行。候选生成器负责目标球、袋口、翻袋、解球、安全球、力量、杆法与自由球位置；`ShotSimulator` 使用正式物理内核试打并评分。

规划输出最终转换为现有瞄准和击球事件。Worker 失败时必须安全回退，主线程和规则状态不能被阻塞。

### 渲染和交互

`src/view/` 管理 Three.js 场景、球桌/球杆外观、材质、环境、相机和 HUD。画质 Profile 决定阴影、DPR、环境反射和降级策略。

相机属于观察层：球在运动、AI 思考或 AI 出杆期间，用户仍可旋转和缩放；视角变化不写入比赛状态。

### 音频

统一音频库按击球、球撞球、碰库和落袋分类。碰撞强度选择采样和音量，接触位置驱动空间声源；低画质设备可以回退为普通立体声。

### 在线同步

消息保持向后兼容，并在接收端用递增序号和有界窗口去重。重连通过快照恢复球位、比分、球组、当前球手和自由球阶段。请勿在缺少兼容方案时改变公开消息结构。

## 资产约束

- 优先使用程序化生成、CC0 或 GPL 兼容资源。
- 记录来源、许可证和必要的处理步骤。
- 保持资源轻量，新增模型和音频应在提交前检查压缩体积。
- 资源失败时必须有程序化模型或静音等可运行回退。

## 兼容性红线

- 相同局面与击球输入必须保持确定性。
- 不破坏现有 URL、分享链接、录像与回放。
- 不让外观选择改变同一规则下的碰撞几何或物理参数。
- 不在 AI 路径中绕过规则或直接修改计分。
